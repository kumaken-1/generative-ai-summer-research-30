# 3ステップ化と役割別デザイン 設計

作成日：2026年7月28日

## 背景

公開版のレビューで、設計思想と実装のずれが一点に集約されることが分かった。

設計書が掲げる成功条件は「AIの返事にもう一言返せるようになる」という行動の変化である。しかし画面が記録していたのは「できたことにする」ボタンを1回押したことだけで、5つの基本動作のどれをしたかは問われなかった。クエストを開いて閉じるだけでも満点になる。

同時に、2通目の文章が完成文として用意されていたため、利用者は自分の考えを一度も言葉にしないままコピーして送っていた。60本中59本が「私は〜」で始まる同一の型で、30回やると同じ文を貼り直している感覚になる。

画面側では、コピーして送る文（`.prompt-box`）と安全上の注意（`.safety-note`）が同一のCSS規則を共有しており、操作すべきものと注意すべきものが見分けられなかった。

## 目的

1. 「もう一言返す」を、利用者が自分の言葉で行う場面として画面に作る。
2. 説明・操作・考える・注意の4つの役割を、見た目で区別できるようにする。
3. 30回やっても実務に使える成果物が一つも残らない状態を解消する。
4. 着手できないクエストをなくす。

## 対象

- 全30クエストの2通目（60本）、学校ルートの本文、入力方式、力の割り当て
- クエスト詳細画面の構成と進捗の記録方式
- 進捗パネル、称号、迷ったときの候補
- 画面のCSS、印刷用ページ、練習用素材

クエストの題名、身につくこと、3エリアの10問ずつの構成、番号、関連参照は変更しない。

## 1クエストの3ステップ

1クエストを次の3つに分ける。3つすべてを終えるとクリアになる。

| ステップ | 内容 |
|---|---|
| ① AIに送った | ①の文章をコピーして生成AIに送る |
| ② 自分の言葉で返した | ②の空欄を自分の言葉で埋め、もう一言返す |
| ③ 使い方を決めた | そのまま使える／直せば使える／使わない から選ぶ |

**順序はロックしない。** 次にやることを見た目で強調するだけにする。押せなくすると、生成AIを開けない利用者が「入力例を読み、どんな返事が来そうか考える」参加を記録できなくなり、設計書の方針に反する。

また、クリックは自己申告であり、実際にAIへ返したかどうかは判定できない。3ステップが与えるのは強制ではなく、②を目に見える作業にすることである。この点を過大に評価しない。

## 2通目の穴あき化

`followUp` を文字列から `{ template, hints }` に変える。

```js
followUp: {
  template: "「____」に違和感があります。もっと普段の言葉にしてください。",
  hints: ["かたい言い回し", "自分が使わない語", "説明が長すぎる"],
}
```

- `template` は半角アンダースコア4つの空欄をちょうど1つ持つ。画面ではここが入力欄になる。
- `hints` は3件。何を書けばよいか分からない利用者のための例で、空欄に入れてそのまま通る語句にする。
- 60本すべて文型を変える。「私は」で始まる型に偏らせない。
- 印刷版では空欄を下線に、例を併記する。

入力欄に書いた言葉は、この端末を含めどこにも保存せず、画面を閉じると消える。入力欄のすぐ下に、個人が分かる言葉を書かない旨を明記する。

## 4つの役割

役割ごとに見た目を固定し、混ぜない。

| 役割 | 該当 | 見た目 |
|---|---|---|
| 説明 | 身につくこと、こんなときに、経験する力 | 装飾なし。見出しは小さく太字のグレー |
| 操作 | ①②の入力例 | 白地に濃い2px枠、①②の番号バッジ、幅いっぱいのコピーボタン |
| 考える | 振り返りの問い、2通目の組み立て | 淡い黄の背景と左罫、「？」の印 |
| 注意 | 安全上の注意、事実確認 | 警告色の枠と「！」の印 |

**警告色は注意の役割以外で使わない。** この規則はテストで機械的に検査する。

安全上の注意は畳まない。自由入力欄を置いた画面なので、常に見えている必要がある。畳んでよいのは「材料の扱い」「生成AIを開けないとき」だけとする。

## 称号

数だけでなく、取り組み方でも増やす。10問目から30問目まで何も起きない空白地帯を埋めるため、未獲得の称号も条件付きで表示する。

数による称号は1・3・5・10・30問。ふるまいによる称号は、同じクエストを日常と学校の両方で試す、3日に分けて取り組む、「使わない」を選ぶ、確かめが必要なクエストを3つ通る、7つの力すべてに1ポイント以上ためる、3エリアそれぞれで1問クリアする。

連続日数と順位付けは作らない。自由参加の企画で「途切れた」を作ると罪悪感になり、「大げさに考えなくなる」という目的に逆行する。

## 迷ったときの候補

どれをやるか決まらない利用者のために、まだ試していないクエストを1つ表示する。「別のクエストにする」で次の候補へ送れる。

**日付には結びつけない。** 検討の過程で、休みの日数30日とクエスト数30問が一致することから日付ごとに1問を割り当てる案を実装したが、これは誤りだったので取り消した。

夏休みは30日、クエストも30問なので一見きれいに対応するが、日付に問題を割り当てた時点で「1日1問」というペースを押しつけることになる。1日に2問やってもよく、何もしない日があってもよく、速さは取り組む人が決める。経過日数を表示しなければ済む話ではなく、日付と結びつけたこと自体が「自由参加」「順番も速さも自由」「1個だけでもよい」という企画の柱に反する。

候補は未クリアのものから順に出す。全部終えたら候補は出さず、やり直しや別ルートを案内する。

## 最終回の個人化

クエスト30の入力例に差し込み口 `{{cleared}}` を置き、その利用者がクリアしたクエスト名を画面側で差し込む。未クリアのときは「いくつかのクエスト」に置き換える。印刷版でも同じ置き換えを行い、記号を紙面に出さない。

AIは利用者が何を試したか知らないため、「これまで試した中で」と書くだけでは架空例を作らせるだけになる。進捗データを持っている画面側が埋める。

## 練習用素材

添付・貼り付けが必要なクエストで、素材を探す手間により着手できない状態を解消する。すべて架空の内容とし、実在の学校・団体・人物と関係ないことを明記する。

- `assets/sample-notice.md`：架空の通知文（要約、根拠の確認）
- `assets/sample-draft.md`：架空の下書き4種（言い換え、統合、部分採用、加筆）
- `assets/sample-screen.svg`：架空の案内画面（見落とし探し、検証手順）

案内画面は、日付を小さく置く、締切を本文から離すなど、見落としが実際に見つかるように作る。

GitHub Pages の配信対象は明示列挙なので、素材の追加時はワークフローにも追記する。追記漏れはリンク切れになるため、テストで固定する。

## 内容の修正

- 学校ルート本文の「架空の」を削除する。前置きは `schoolPrompt()` が自動挿入するため二重になっていた。個人情報を書かないことと架空設定にすることは別であり、架空指定はAIに一般論を返させ、実務で使える成果物が残らない原因になっていた。
- 入力方式を実態に合わせる。11・19・20・24 は貼り付ける素材が本文に直書きされており、貼り付ける必然性がなかった。29 は添付が不要だった。
- 力の割り当てを直す。13は写真にない物を推測と分ける回なので真実を映す鏡、12は初めて写真を添付する回なので情報守りの盾、8は教育用語の説明でAIが誤りやすいので真実を映す鏡、30は最終回なので主体性の剣を主とする。
- 8に事実確認を追加する。
- 力ごとの総ポイントはそろわない。その力を使うクエストの数であり重要度ではないことを画面に明記する。
- 重複していた7つの群で、題材と動作を分ける。

## 進捗データ

保存形式を v2 に変える。旧 v1 のクリア記録は3ステップ完了として引き継ぎ、初回読み込み時に新形式へ書き戻す。入力欄に書いた言葉は保存対象に含めない。

## 公開時期

まだ誰も取り組んでいないため、全面的に差し替える。期間の途中で体験が断絶する利用者はいない。

旧形式の進捗データは自動で移行するので、仮に途中まで進めた端末があっても記録は失われない。
