# 初心者向け語彙・携帯操作改善 設計

## 目的

「生成AI 夏の自由研究30」を初めて生成AIに触る学校職員が携帯電話から利用しても、次に何をすればよいか迷わない案内へ改善する。

ゲームらしさは残すが、ゲーム用語だけで操作を説明しない。サイト自体が生成AIではなく、ChatGPTなどの生成AIで試す文章と手順を案内するサイトであることを明記する。

## 対象

- トップページの導入説明、進捗、絞り込み、クエストカード
- 全30クエストの詳細画面
- コピー後の案内
- 文字、写真、文章貼り付け、文書添付、画像添付の手順
- 640px以下を中心とする携帯表示
- 印刷用ページの共通語彙

クエストのテーマ、30回の順序、安全条件、事実確認の内容、進捗データ形式は変更しない。

## 初心者向け語彙

次の基準で語彙を統一する。

| 現在 | 変更後 |
|---|---|
| クエスト | 初出では「クエスト（小さなお題）」と説明し、その後はクエスト |
| 最初の一言 | まず、この文章を生成AIに入力してみよう |
| 自分の考えを、もう一言 | AIの回答を読んだら、続けてこの文章を入力しよう |
| 入力文をコピー | この文章をコピー |
| 入力方法 | 生成AIで使うもの |
| 文字入力 | 文字だけ |
| 日常で試す | 日常の困りごとで試す |
| 学校で試す | 学校の困りごとで試す |
| 自分はどう思う？ | AIの回答を読んで、合わないところを考えよう |
| クリアにする | できたことにする |
| クリアを取り消す | できた記録を取り消す |
| 事実を確かめる | AIの回答が正しいか、元の資料と比べよう |

ボタンは短い動詞にし、その直前またはコピー後の通知で次の操作を説明する。「この文章をコピー」は、通知で「コピーしました。ChatGPTなどの生成AIを開いて貼り付けてください」と補う。

## 初回の3手順

トップページの最初の画面内に、次の3手順を表示する。

1. 気になるクエストを一つ選ぶ
2. 表示された文章をコピーする
3. ChatGPTなどの生成AIを開き、文章を貼り付けて送る

「生成AIの回答が正解とは限らない」「回答を読んで、自分の考えを続けて入力する」ことも同じ案内内に短く示す。

## 入力方法別の手順

詳細画面では `inputMode` に応じ、生成AI側で行う操作を具体的に表示する。

- 文字だけ：文章をコピーし、生成AIの入力欄へ貼り付けて送る
- 写真：個人情報が写っていないことを確認し、生成AIの画面で撮影または写真を選んで添付してから文章を送る
- 文章を貼り付け：個人情報を除いた文章を生成AIの入力欄へ貼り付け、続けて指定の文章を送る
- 文書を添付：個人情報を含まない公開可能な文書だけを、生成AIの画面で添付してから文章を送る
- 画像を添付：個人情報を隠した公開可能な画像だけを、生成AIの画面で添付してから文章を送る

特定サービスのボタン位置やアイコンは端末・サービスで異なるため断定しない。「ChatGPTなど」という例示に留める。

## 携帯表示

640px以下では次を満たす。

- クエスト一覧は1列
- 絞り込み、ルート切替、コピー、完了、お気に入りの主要ボタンは原則として横幅いっぱい
- すべての操作対象は44px以上
- 詳細ダイアログは画面幅と画面高に収まり、本文だけが縦スクロールする
- 詳細上部のタイトルと「閉じる」はスクロール中も見つけられる
- 長い日本語、URL、ボタン文言で横スクロールを発生させない
- `100dvh`を使い、携帯ブラウザのアドレスバー表示変化に耐える

## 7つの力とポイント

教職員が身に付けたい次の7つの力を、ゲーム内の成長単位として使用する。

1. 主体性の剣
2. 情報守りの盾
3. 仕事選びの羅針盤
4. 指示の魔法袋
5. 対話の杖
6. 真実を映す鏡
7. 仕上げのたい焼き

各お題には「主となる力」を1つ、「一緒に使う力」を1つ設定する。お題を「できたことにする」と両方へ1ポイントずつ加え、記録を取り消すと両方から1ポイントずつ戻す。1題2ポイント、全30題で全体60ポイントとする。

分類と力ごとの総ポイントは、承認済みの別紙 `2026-07-27-seven-powers-classification-draft.md` を使用する。

| 力 | 総ポイント |
|---|---:|
| 主体性の剣 | 10 |
| 情報守りの盾 | 7 |
| 仕事選びの羅針盤 | 7 |
| 指示の魔法袋 | 12 |
| 対話の杖 | 11 |
| 真実を映す鏡 | 6 |
| 仕上げのたい焼き | 7 |

進捗欄には次を表示する。

- 全体：`獲得ポイント / 60ポイント`
- お題：`できたお題数 / 30お題`
- 各力：`獲得ポイント / その力の総ポイント`
- 各お題カード：主となる力
- 詳細画面：主となる力と一緒に使う力
- 完了時：加わった二つの力とポイント

ポイントは能力評価ではなく、その力を使う体験をした回数であると進捗欄の近くに明記する。力ごとの総ポイントの違いは重要度の違いではない。色だけに頼らず、名称、数字、進捗バーを併用する。

## 「7つの力」画像ガイド

トップページに「7つの力を見る」ボタンを設置する。ボタンを押すと、アクセシブルなダイアログで次を案内する。

- 見出し：「生成AIを使うときに大切な7つの力」
- ポイントの意味
- 軽量化した「７つの力」の画像
- 画像を大きく見る操作
- 7項目の短い文章説明
- 常に見つけやすい「閉じる」ボタン

画像だけに情報を依存させず、同じ内容の文章ガイドを設ける。`public_site` の親フォルダにある元画像 `７つの力.png` は1055×1491px、約4.04MBであり、変更も公開リポジトリへのコピーもしない。

公開用には次の派生画像を作る。

- 携帯向け：横幅720pxのWebP
- 拡大表示向け：横幅1055pxのWebP
- 2画像合計は原則1MB未満
- ボタンを押すまで画像を読み込まない
- 携帯向け画像を優先し、画面条件に応じて高解像度版を選ぶ
- 圧縮後は図中の小さい日本語が読めるか原寸表示と携帯表示で目視確認する

高解像度画像は新しいタブでも開けるようにし、携帯ブラウザの拡大操作を利用できるようにする。

## アクセシビリティ

- 既存の見出し構造、ネイティブボタン、`dialog`、フォーカス復帰、ライブリージョンを維持する
- 語彙変更後もボタン単体で目的が分かる名前にする
- 色だけで状態を伝えない
- キーボード操作とEscapeでのダイアログ終了を維持する
- 携帯向け変更でも200%拡大時に横スクロールを生まない

## テスト

実装前に、現在の語彙では失敗する契約テストを追加する。

- 禁止する曖昧語と、必要な初心者向け語彙
- トップページの3手順
- 5種類の入力方法に対応する具体的手順
- コピー後の次の操作案内
- 全30題に主となる力と一緒に使う力が一つずつあり、力ごとの総ポイントが `9, 7, 7, 13, 11, 6, 7`、全体が60になること
- 完了と取り消しで、該当する二つの力の獲得ポイントが増減すること
- 「7つの力を見る」ボタン、画像ガイド、文章ガイド、遅延読込
- 公開用画像2点の寸法、形式、合計容量
- 390×844、820×1180、1440×1000で横方向のはみ出しがないこと
- 390×844で主要ボタンが44px以上で、詳細を開閉・切替・コピー・完了できること
- 390×844で7つの力ガイドを開閉し、画像を拡大表示できること
- 印刷ページと画面の共通語彙が同期していること

通常テスト、Chromiumスモークテスト、GitHub Actions、公開URLでの最終確認を通過してから公開完了とする。

## 完了条件

- 初心者がトップページと一つの詳細画面を読むだけで、生成AIへ何を入力するか判断できる
- 写真・文書はこのサイトではなく生成AIの画面で添付すると分かる
- 携帯で横スクロールせず、主要操作を無理なくタップできる
- 7つの力それぞれを `獲得ポイント / 総ポイント` で確認できる
- 全30題を終えると全体60ポイントとなり、7項目がそれぞれ満点になる
- 4.04MBの元画像を公開せず、読みやすい軽量画像と文章で7つの力を確認できる
- ゲーム性、安全条件、30回の学習順序、ローカル保存が維持される
