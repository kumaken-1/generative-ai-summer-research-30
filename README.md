# 夏休み限定　生成AI 夏の自由研究30

生成AIにまだ慣れていない小学校の教職員が、日常や学校の小さな困りごとを入口に「ちょっと使ってみよう」と思えるようになるための、30個のミニクエストです。夏休み中に公開し、気になるものを1個だけでも試せる場を目指しています。

## 参加のしかた

- 自由参加です。30回すべてを終える必要はありません。
- 順番も速さも自由です。1日に何個やっても、間があいてもかまいません。ただし、最初の10回は文字だけのやり取りを中心にし、生成AIとの対話に慣れられるようにしています。
- 11回目以降は、写真の撮影・画像の添付・文章の貼り付け・文書の添付を少しずつ体験します。
- ランキング、提出、成績評価はありません。取り組んだ数を競う企画でもありません。
- 生成AIを開けない場合も、入力例を読み「どんな返事が来そうか」を考えるだけで参加できます。

## 大切にしていること

生成AIの回答は「正解」や「完成品」ではなく、考えるための下書きです。回答を読んだら、自分の考え、好み、条件、違和感をもう一度伝え、対話を続けてください。

事実に関わる内容は、元の文書、公的機関の情報、別の信頼できる資料などでファクトチェックします。最後に採用するか、直すか、使わないかを決めるのは利用者自身です。

## プライバシーとデータ

- 児童・保護者・職員の氏名、顔、連絡先、成績、健康情報などの個人情報や、学校の機密情報を入力・撮影・添付しないでください。
- 練習には、公開済みの資料、個人を特定できない写真や文書、同梱の練習用素材を使ってください。
- 2通目を組み立てる入力欄がありますが、書いた言葉はこのサイトの外へ送らず、端末にも保存しません。画面を閉じると消えます。
- 進み具合とお気に入りは、利用中の端末の `localStorage` にだけ保存します。入力内容や生成AIの回答は収集しません。
- 外部API、アクセス解析、広告、トラッカーは使用しません。生成AIサービスとの通信もこのサイトからは行いません。

### 練習用の素材

「文書を添付」「画像を添付」「文章を貼り付け」のクエストでは、探す手間で止まらないよう練習用の素材を同梱しています。すべて架空の内容で、実在の学校・団体・人物とは関係ありません。

- `assets/sample-notice.md`：架空の通知文（要約・根拠の確認に使う）
- `assets/sample-draft.md`：架空のお便り下書き（言い換え・部分採用に使う）
- `assets/sample-screen.svg`：架空の案内画面（見落とし探し・検証手順に使う）

## 使い方

初めて使うときは、次の3段階で進めます。

1. 気になるクエストを選ぶ
2. 文章を生成AIに入力する
3. AIの回答を読んで、続けて文章を入力する

画面は携帯にも対応しています。パソコンの前に座らなくても、手元の携帯でクエストを選び、入力例を見ながら試せます。

### 1クエストの3ステップ

各クエストは、次の3つを終えるとクリアになります。次にやることが目立つように表示されますが、順番は強制しません。

1. **AIに送った**：①の文章をコピーして生成AIに送る
2. **自分の言葉で返した**：②の空欄を自分の言葉で埋め、もう一言返す
3. **使い方を決めた**：そのまま使う／直せば使える／使わない のどれかを自分で選ぶ

②の空欄は、あらかじめ用意した文をそのままコピーするのではなく、AIの回答を読んで感じたことを自分で入れる場所です。何を書けばよいか迷うときは、例を3つ用意してあります。

③はどれを選んでもクリアになります。「使わない」も立派な判断で、選ぶと称号が一つ増えます。

生成AIを開けないときは、入力例を読んで「どんな返事が来そうか」を考えるだけでも参加できます。押せるステップを制限していないのは、この参加のしかたを妨げないためです。

### 迷ったときの候補

どれをやるか決まらないときのために、まだ試していないクエストを1つ表示します。「別のクエストにする」で次の候補に送れます。

**日付とは結びつけていません。** 1日に何個やっても、やらない日があってもかまいません。「今日は何問目」という決まりはなく、進める速さは取り組む人が決めます。

### 称号

称号は、クリアした数だけでなく、取り組み方でも増えます。同じクエストを日常と学校の両方で試す、3日に分けて取り組む、「使わない」を選ぶ、確かめが必要なクエストを3つ通る、といったふるまいがそれぞれ称号になります。未獲得の称号には条件が表示されるので、次に何を試すかの目安になります。

### 7つの力

各クエストを終えると、「7つの力」のうち主となる力と一緒に使う力に1ポイントずつ加わります。初めは全体が `0/60` で、各項目も「獲得ポイント/総ポイント」の形で表示されます。これは能力評価ではなく、どの力を使う体験を何回したかを示す体験回数です。

力ごとの総ポイントはそろっていません。これはその力を使うクエストの数であり、数が多い力ほど大切という意味ではありません。

### GitHub Pages

公開後はGitHub PagesのURLをブラウザで開くだけで使えます。クエストを選び、「日常ルート」または「学校ルート」の入力例を、自分が利用できる生成AIサービスで試してください。

### ローカルで見る

このリポジトリを取得し、プロジェクト直下で静的ファイルを配信します。

```powershell
python -m http.server 4173
```

その後、`http://localhost:4173/` をブラウザで開きます。ビルドツールやAPIキーは不要です。

## 開発・確認

Node.js 22以降を想定しています。

```powershell
npm test
npm run build:print
npm run test:smoke
```

- `npm test`: 内容、状態保存、画面構造、公開文書のテスト
- `npm run build:print`: `js/quests.js` から印刷用の `print.html` を再生成
- `npm run test:smoke`: 利用可能な場合にブラウザで主要操作を確認

## 内容を更新する

クエスト本文の正本は [`js/quests.js`](./js/quests.js) です。更新後は `npm run build:print` を実行し、通常画面と印刷用ページの内容をそろえてから `npm test` を実行してください。生成済みの `print.html` だけを直接編集しないでください。

「7つの力」の元画像 `７つの力.png` は、約4MBとファイル容量が大きいため公開リポジトリに含めません。画像を更新するときだけ、リポジトリの親フォルダへ元画像を置き、`npm run build:powers` を実行してください。公開用の軽量な `assets/seven-powers-720.webp` と `assets/seven-powers-1055.webp` が生成されます。生成後は `npm test` を実行し、元画像を公開リポジトリへ追加しないでください。

改善提案や誤りの報告は、公開リポジトリのIssueまたはPull Requestで歓迎します。実在する児童・保護者・職員や学校内部の情報は、Issue、Pull Request、サンプルデータ、画像のいずれにも含めないでください。企画の目的、初心者向けの言葉、既存の安全方針を保つ小さな変更を優先します。
